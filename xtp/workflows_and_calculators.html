12. Workflow and Calculator Structure¶

A typical workflow for a morphology from molecular dynamics (see the QMMM_GROMACS tutorial) is

  1. xtp_map -t topol.tpr -c conf.gro -s system.xml -f state.hdf5: map the MD configuration to molecules (segments) with the mapping file system.xml, which also refers to the QM geometries and the multipole/polarizable (MPS) files of each segment and state; xtp_run -e mapchecker writes the mapped structures as .pdb files for inspection.

  2. xtp_run -e neighborlist: pairs of neighbouring segments.

  3. xtp_run -e einternal: reads internal (gas-phase) site energies and reorganization energies (e.g. -c energies_file=system.xml) into the state file.

  4. Site energies in the environment, e.g. xtp_parallel -e qmmm with classical regions only, followed by xtp_run -e eanalyze.

  5. Electronic couplings: xtp_parallel -e eqm (single-molecule DFT/GW-BSE), then xtp_parallel -e iqm (couplings of all pairs), or xtp_parallel -e iexcitoncl for classical exciton couplings; xtp_run -e ianalyze summarizes them.

  6. Transport: xtp_run -e kmcmultiple (bulk mobility), kmctof and grw (time of flight), kmclifetime (exciton diffusion), see Transport Simulations.

The xtp_parallel calculators work in three steps: -j write writes a job file with one job per segment or pair, -j run runs the jobs (-t jobs at the same time, each with -x OpenMP threads; several processes can work on the same job file, each taking -q jobs at a time), and -j read reads the results back into the state file.
