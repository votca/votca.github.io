11. XTP ASE Interface¶

The Python package pyxtp provides an ASE calculator xtp that runs DFT and GW-BSE calculations (the dftgwbse tool) on an ase.Atoms object.

11.1. Installation¶

The interface is built with VOTCA-XTP if pybind11 and the Python development files are found by CMake. make install installs the compiled bindings and, if the Python modules ase, xmltodict, h5py, lxml and rdkit are available, the pyxtp package into the Python user site-packages directory (set CMAKE_INSTALL_PYTHON_LIBDIR to choose another directory). The plotting functions of Visualization also need matplotlib.

11.1.1. Environment variables¶

The environment variable VOTCASHARE must be defined in order for the interface to find the default xml files and create the options data structure. You can set this environment variable in your shell configuration file (VOTCARC.bash sets it, too):

$ export VOTCASHARE=<installation prefix>/share/votca

Or within python itself:

>>> os.environ['VOTCASHARE'] = '<installation prefix>/share/votca'

11.2. Options¶

All options of the dftgwbse tool are available in the options attribute of the calculator (an instance of pyxtp.options.Options), which mirrors the XML option files, e.g. calc.options.dftpackage.basisset or calc.options.gwbse.gw.mode. Options that are not changed keep their default values (see dftgwbse). XC functionals are given by their libxc names, e.g. XC_HYB_GGA_XC_PBEH (the default) or XC_GGA_X_PBE XC_GGA_C_PBE.

11.3. XTP calculator¶

xtp(label=None, nthreads=1, options=None, directory='./', **kwargs)

  • nthreads: number of threads of the calculation

  • options: an Options object to start from (default: the defaults of dftgwbse)

  • further keyword arguments are passed to set

Frequently used options can be specified with the calculator’s set routine (or as keyword arguments of the constructor):

Other options can be set with set by their path, e.g. calc.set(**{'dftpackage/auxbasisset': 'aux-def2-svp'}).

11.4. Results¶

Besides get_potential_energy() and get_forces() (ASE), the calculator provides e.g. get_dft_energy(), get_qp_corrections() and get_oscillator_strengths(dynamic=False). pyxtp.Visualization(atoms) plots quasiparticle corrections, densities of states and absorption spectra.

11.5. Forces¶

select_force(energy='energy', level=0, dynamic=False) chooses the energy whose forces get_forces (and therefore an ASE optimizer) uses:

energy

energy

'energy'

DFT total energy (analytic forces if the DFT engine provides them, otherwise finite differences)

'ks'

total energy with Kohn-Sham level level excited

'qp'

total energy with quasiparticle level level excited

'singlets'

BSE singlet level (dynamic=True: with dynamical screening)

'triplets'

BSE triplet level (dynamic as for singlets)

All energies except 'energy' use finite differences of the total energy (displacement eps=0.001 Å in get_forces), i.e. one full DFT and GW-BSE calculation per displaced coordinate.

11.6. Excited-state dipoles by finite fields¶

pyxtp.finite_field.FiniteFieldDipoles computes the change of the dipole moment on excitation, \(\Delta\mu_n = \mathrm{d}\Omega_n/\mathrm{d}F\), and the diagonal of \(\Delta\alpha_n = -\mathrm{d}^2\Omega_n/\mathrm{d}F^2\) from GW-BSE excitation energies \(\Omega_n\) in small uniform fields (dftpackage.externalfield), together with the ground-state dipole and polarizability from the DFT energy. Unlike the dipole of the excited-state density (Orbitals::DensityMatrixFull, which is the unrelaxed difference density \(XX^T + YY^T\)), these are relaxed: they include the response of the orbitals, of the quasiparticle energies and of the screened interaction. For charge-transfer states the two can differ by a factor of about two.

from ase.io import read
from pyxtp import xtp
from pyxtp.finite_field import FiniteFieldDipoles, write_xml

calc = xtp()
calc.set(basis='def2-tzvp', **{'dftpackage/auxbasisset': 'aux-def2-tzvp'})
ff = FiniteFieldDipoles(read('molecule.xyz'), options=calc.options,
                        nthreads=4, components='xyz', nstates=5)
result = ff.run()
print(result.table())
write_xml(result, "dipoles.xml")

  • Each field component needs two dftgwbse runs (order=2, field step field=1e-3 Hartree/bohr) or four (order=4, which also reports a linearity check), plus one run without field. The runs are kept in workdir and reused if the calculation is repeated, e.g. with more components.

  • The SCF is converged with convergence_tightness=verytight; the field changes the energies by only about \(10^{-4}\) Hartree. Self-consistent GW (evGW) must be well converged, too: a GW window whose highest levels have two quasiparticle solutions can make the differences noisy (use an explicit qpmax/bsemax below such levels).

  • States are matched between the runs by the overlap of their BSE amplitudes, after transforming them into the zero-field orbitals, so that states which cross in the field are followed correctly. States that mix with others, or that are matched with an overlap below overlap_threshold, are marked; for groups of mixing states the derivative of the sum of their energies is given as well, which is reliable even when the individual values are not.

  • Conventions: atomic units; externalfield adds \(-\mathbf{F}\cdot\mathbf{r}\) to the one-electron Hamiltonian, so that \(\mathrm{d}E/\mathrm{d}\mathbf{F}\) is the dipole moment. The ground-state dipole is given with respect to the centre of mass (the origin of the field operator).

The command-line script xtp_excited_dipoles wraps this class. It is installed only together with pyxtp (see Installation) and has to run with the Python interpreter pyxtp was installed for. Example: xtp_excited_dipoles -x molecule.xyz -o options.xml -t 4 --xml result.xml, where options.xml holds dftgwbse options as for xtp_tools.
